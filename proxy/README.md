# 对话记录

**在第三方服务器上打牌 / 观战，把对局对话录下来。**

这个目录里有**两个**工具，解决同一件事的两种做法：

| | 怎么用 | 适合 |
|---|---|---|
| **代理** | 把客户端的服务器地址改成 `127.0.0.1`，你在自己电脑上正常打牌 | **自己下场打**——你自己说的话也只有这样才录得到 |
| **观战** | 电脑上**不用开客户端**，填个服务器 + 房间名就挂着录 | **盯别人的局**——开着电脑挂机，不占你的客户端 |

两个输出的都是 `.yrp3d`。用界面的话查看和导出都在页面里；命令行版拖进 `../chat-extractor.html`。

> **服务器地址已经填好了。** 界面里的「服务器地址 / 端口」预填的就是
> `example.com:888`，命令行版第一次问的时候括号里也是它，直接回车即可。
> 要连别的服务器就把它覆盖掉 —— 三个地方（`proxy.js` / `observer.js` / `gui.js`）
> 各有一份默认值，`_test_gui.mjs` 会断言它们一致，改的时候别漏。

**双击哪个**——推荐从界面进，两种模式都在里面：

| 双击 | 是什么 | 适合 |
|---|---|---|
| **`START.vbs`** | 浏览器里点按钮，**录完直接在里面看对话**。全程**没有黑窗口** | **推荐** |
| `gui-console.bat` | 同一个界面，但会开一个黑窗口显示日志 | 界面双击了没反应时用它看报错 |
| `proxy.bat` | 命令行版代理 | 想要一个能一直开着的窗口 | 
| `observer.bat` | 命令行版观战 | 同上 |

界面只是**替你把这两个命令行程序开起来**（子进程），功能完全一样，
录出来的文件也一样。命令行版不会因为有了界面就被砍掉。

> 观战端只**看**：发完进房间的握手包之后就不再说话了，也不会占用玩家座位——
> 它先按普通玩家进去（协议上没别的办法），一发现自己被安排到座位上就立刻
> 发切换观战，和真人点「观战」是同一套动作。观战者不受服务器心跳约束，可以一直挂。

## 模式零：界面（推荐）

> **前置要求：装了 Node.js —— 或者用打包好的 exe。** 这个目录**全部**都跑在 Node 上——
> 录制要靠它开 TCP（浏览器没有这个 API），界面是 `node gui.js` 起的一个只监听 `127.0.0.1`
> 的小服务，`START.vbs` 做的只是把它在没有黑窗口的情况下拉起来。
> **零 npm 依赖**，装完 Node 就能用，不用 `npm install`。
>
> 四个启动器**都是先找同目录的 `yrp.exe`，找不到才退回 `node`** —— 所以同一个文件
> 在开发树和发布包里都能双击。整包封装成单个 exe 只要 `node build-release.mjs`，
> 见 [`../PACKAGING.md`](../PACKAGING.md)；对方拿到发布包**什么都不用装**。
>
> 只想给「看录像 + 导出」的话，给 `../chat-extractor.html` 那**一个文件**就行，
> 双击即用、自包含，导出结果和界面里逐字节一致（同一份代码）。

双击 **`START.vbs`**，浏览器会自动打开一个页面——**没有任何黑窗口**。
两种模式在里面各是一个标签页，点「开始记录」就行，**录完直接在页面下面看对话**。

```
┌ 观战记录 │ 自己打牌（代理） ┐
│  服务器地址 / 端口 / 房间名 / 昵称   [开始记录] [停止]  ● 记录中
│  ── 实时日志（诊断用）──
│  ...
│  ── 录像（每 2 秒刷新）──
│  把 .yrp3d 文件或整个文件夹拖到这里 —— 也可以 [选择文件…] [选择文件夹…]
│  [全选] [全不选] 已勾 2 个      ☐排除系统消息 ☐排除观战发言
│  [合并 TXT] [分文件 TXT] [JSON] [CSV] [复制全部]
│  [📁 导出目录…] 导出到：浏览器下载目录
│  ☑ 示例房-09-25「16：57：48」.yrp3d        录制中  1.6 KB
│  ☑ 09-25「13：09：46」.yrp3d                        2.1 KB
│  ☐ 本机.yrp3d  本机                                 3.4 KB
│  ── 对话 · 09-25「13：09：46」.yrp3d ──  [搜索……] [全部消息 ▾]
│  小明      :: 你好
│  观战者    :: 围观一下
└──────────────────────────────┘
```

**日志和对话是两回事**：上面那块日志只是给你看程序在干什么（连上没有、让座没有）；
下面那块对话是从 `.yrp3d` 文件里**解析出来的**，名字、说话者身份都以文件为准。
所以正在录的时候它每 2 秒重读一遍最新那个文件——看到的就是实时对话。

### 导出

左边每个录像前面的**方框勾上**，就能一起导出。四种格式：

| 按钮 | 产出 |
|---|---|
| **合并 TXT** | 一个文件，每个录像一段，段落头是 `### 文件名` |
| **分文件 TXT** | 每个录像一个 `.txt`，文件名是 `原名_chat_<时间戳>.txt` |
| **JSON** | 一个文件，每个录像一条记录（含偏移、说话者类型、座位） |
| **CSV** | 一个文件，Excel 能直接开。带 UTF-8 BOM，中文不会变乱码 |
| **复制全部** | 和「合并 TXT」同样的内容，直接进剪贴板，不落盘 |

两个勾选框（**排除系统消息** / **排除观战发言**）对**上面每一种**都生效，
「复制全部」也一样。只想看双方玩家说的话就两个都勾上。

**文件名都带导出时间**（`录像对话汇总_20260925-143012.txt`），所以重复导出不会覆盖上一次。
同一次「分文件 TXT」里的所有文件**共用一个时间戳**，方便认出是同一批。

导出完成右下角会弹一个提示，写明导出了几个、存到哪了，**文件名能点**——
点一下在新标签页里看一眼内容（是同一份内容的浏览器副本，不是磁盘上那个文件）。

#### 导出到哪里

默认走**浏览器自己的下载**，文件进下载目录。想固定位置就点 **「📁 导出目录…」** 选个文件夹，
之后所有导出都进那里。那一行提示一直写着当前目标。

> 这个按钮要 Chrome / Edge（依赖 File System Access API）。别的浏览器会弹一句说明，
> 然后照常退回下载目录，不会静默丢文件。
>
> 一次导出很多文件时，浏览器可能问一句「是否允许下载多个文件」——
> **允许了才会全部存下来**；被拒的话只有第一个会落盘。嫌烦就先指定导出目录。

### 把本机的录像拖进来

不光是刚录的，**你以前用别的工具存下的 `.yrp3d` 也能一起处理**：

- 把文件（或整个文件夹）**拖到录像面板上**，也可以点「选择文件…」「选择文件夹…」
- 拖进来的排在列表最前面，带一个「本机」标记
- 可以和服务器上录的那些**一起勾、一起导出**

> 这些文件**只在浏览器里解析，一个字节都不上传**——所以多大的文件都行，
> 也不会在服务器上留下副本。代价是**刷新页面就没了**（服务器上的录像不受影响），
> 想清掉就点「清空拖入的文件」。
>
> 顺带一提，这也是为什么拖进来的文件解析得比服务器上的快：不用走网络，也不用落盘。

| 要干什么 | 怎么做 |
|---|---|
| 停止录像 | 点「停止」。界面留着，可以接着录下一局 |
| **关掉整个界面** | 点右上角**「退出界面」**。正在录的话会一起停（会先问你一句） |
| 页面不小心关了 | **再双击一次 `START.vbs`** —— 它发现界面还在跑，就只把页面重新打开，不会开第二个 |
| 界面双击了没反应 | 改用 `gui-console.bat`，报错会显示在窗口里 |

> 页面只监听 `127.0.0.1`，并且地址上带一个随机 token ——
> 别的程序访问不到，你自己刷新 / 重开浏览器也不用重新登录。

**退出必须从页面点。** 没有窗口可以关，所以别去任务管理器找进程 —— 点「退出界面」。

**想换个端口**：界面默认用 `7912`。被占了它会自己换一个。
这个端口和代理的「本机监听端口」没关系，撞上了也不用管。

**出错了看哪里**：启动失败（比如没装 Node）会**弹一个窗**告诉你，同时把详细内容写在
`gui-error.log` 里。正常退出不会留下这个文件——**看到它存在就说明上次不是正常退的**。

## 模式一：代理（自己打牌）

**为什么需要它**

标准 ygopro 客户端打牌时存的 `.yrp` 录像**只记录操作**（出了哪张卡、点了哪个按钮），
**不记录对话**。对话虽然在网络上传了，但没进录像文件，事后补不回来。

服务器也不是你能改的——所以只剩一个办法：**在自己的客户端和服务器之间插一个中转**。

```
ygopro 客户端 ──► 127.0.0.1:<本机端口> ──► 第三方服务器
                        │
                        └─► replays/09-25「14：32：42」.yrp3d
                                  │
                                  └─► 界面里勾选导出（命令行版则拖进 ../chat-extractor.html）
```

代理只**看**不改：转发过去的字节和客户端发来的完全一样，对局本身不受影响。
它抓的是**你自己电脑上自己的客户端**的流量，不碰服务器。

录下来的文件是 `.yrp3d` 格式，**界面里可以直接查看和导出**——搜索、筛选观战发言、
排除系统消息、批量导出那一整套都在。命令行版没有界面，把 `replays/` 里的文件拖进
`../chat-extractor.html` 即可，两边行为一致（导出格式是同一份代码，见
[../README.md](../README.md#共享的解析块改代码前必读)）。

---

### 三步走

#### 1. 双击 `proxy.bat`

第一次运行会问你三件事（括号里是默认值，直接回车就是它）：

```
第三方服务器地址（域名或 IP）（回车 = example.com）: example.com
第三方服务器端口（回车 = 888）: 888
本机监听端口（客户端等一会儿要连这个）（回车 = 888）: 888
```

就是你平时在客户端里填的那个地址和端口。填完记在 `config.json` 里，以后不再问。

> 「本机监听端口」保持和服务器端口一样就行。只有当系统提示端口被占用时才需要改。

#### 2. 客户端改成连本机

打开 ygopro，把服务器地址改成 **`127.0.0.1`**，端口改成**上面第三步填的那个**。

然后正常打牌 / 观战。代理窗口会实时打印它收到的东西：

```
[14:32:42] 已连上 example.com:888
[14:32:47] 我的昵称：RLX
[14:33:01] RLX: 你好
[14:33:05] 新人: 你好啊
[14:33:12] 观战者: 围观
[14:35:20] 断开：09-25「14：32：42」.yrp3d —— 3 条对话，245 字节
```

#### 3. 打完看对话

用界面的话，`录像` 面板里点一下文件就能看，勾上就能导出（见下面的「导出」一节）。
命令行版去 `proxy/replays/` 把 `.yrp3d` 拖进 `../chat-extractor.html`，跟平时用录像一样。

## 模式二：观战（盯别人的局）

**电脑上不用开客户端。** 双击 `observer.bat`，第一次运行问你四件事（同样，括号里是默认值）：

```
第三方服务器地址（域名或 IP）（回车 = example.com）: example.com
第三方服务器端口（回车 = 888）: 888
房间名（要和客户端里填的完全一致）: 朋友的房
观战用的昵称（服务器要一个名字）: 观战记录
```

然后它就自己连上去、进房间、静默录对话：

```
[14:32:42] 已连上，正在加入房间…
[14:32:42] 新连接 -> 朋友的房-09-25「14：32：42」.yrp3d
[14:32:43] 占了玩家位，切换到观战…
[14:33:01] 房主: 你好
[14:33:05] 挑战者: 好久不见
[14:40:12] 断开：朋友的房-09-25「14：32：42」.yrp3d —— 2 条对话，318 字节
```

想停就按 **Ctrl+C**，或者直接关窗口。录像在同一个 `replays/` 目录里，
文件名前面带房间名（`朋友的房-09-25「…」.yrp3d`），和代理录的区分得开。

重填配置：`node observer.js --config`。

### ⚠️ 房间名必须完全一致

这是最容易踩的坑。服务器的行为是「**按名字找房间，找不到就新建一个**」
（`ygopro-server.coffee:764`）。所以房间名打错一个字母，它不会报错，
而是**给你开一个没人进的空房间**，你就对着空房间录半天。

程序 20 秒后如果还没见到玩家或对话，会打印一条提醒。真遇到了就核对
`observer.json` 里的 `room`：

- **区分大小写**
- **带密码的房间**要写成 `房间名$密码`（`$` 是服务器约定的分隔符）
- 最长 19 个字，超了会被截断（`observer.bat` 会提醒）

### 版本号会自动学

不同服务器的版本号可能不一样（服务器配置里一个数字，客户端源码里另一个）。
填错不用管：服务器会把正确版本告诉你，程序自动改写 `observer.json` 再连一次。

### 房主关房间后不会自动重连

故意的。房主一走，重连只会让服务器给你**新建一个空房间**。要接着盯就再跑一次。

## 常见问题

**打不开 / 连不上服务器**

代理窗口会打印 `连不上 xxx:888 —— ...`。检查 `config.json` 里的地址和端口是不是填错了。
确认没问题就再跑一次 `node proxy.js --config` 重填。

**提示端口被占用**

说明已经开着一个代理了，或者别的程序占了 888。用 `--config` 把「本机监听端口」改成
别的（比如 889），然后记得客户端那边也要跟着改。

**录像里只有系统消息，没有玩家说的话**

先确认说话的时候代理窗口有没有跟着打印。没有的话说明对话走的是别的通道，把
`replays/_dump_*.log`（见下）发出来看看。

**观战者没有名字**

和 `.yrp3d` 录像一样：这个格式里观战发言只有内容、没有名字，多个观战者同时说话分不出来。
只有服务器开了 `display_watchers` 才带名字，那时会显示成 `观战者「名字」`。

**打完发现生成好几个文件**

一个 TCP 连接一个文件。掉线重连、或者客户端重开，就会多一个。这是正常的。

**观战连不上 / 录不到**

先看窗口里有没有 `连不上 xxx:888 —— ...`（地址端口错）。
没有的话跑 `node observer.js --dump`，它会把收到的每个包倒进
`replays/_dump_*.log`，断开时还会打印包类型统计——正常至少该有 `0x20`（座位）。
一条都没有就是根本没进到房间里，多半是房间名不对（见上面的警告）。

**标签决斗（2v2）**

座位 2、3 的名字解析不出来，他们的发言会显示成 `系统2` / `系统3`。这条暂时没做。

## 诊断模式

如果收到的对话不对劲（或者一条都没有），跑：

```bash
node proxy.js --dump
```

界面上勾「诊断模式」再点开始，效果一样。

它会把**每一个包**的类型、长度、十六进制倒进 `replays/_dump_*.log`。
断开连接时控制台还会打印这次见到的包类型统计：

```
见到的包类型：0x01×40 0x13×1 0x16×3 0x19×3 0x20×2 0x21×3
```

正常的话应该能看到 `0x19`（对话）和 `0x20`（座位名字）。
一个 `0x19` 都没有，就是服务器没走标准协议。

## 配置项

代理用 `config.json`：

```json
{
  "remoteHost": "example.com",
  "remotePort": 888,
  "listenPort": 888,
  "recordOwnChat": false
}
```

| 字段 | 说明 |
|---|---|
| `remoteHost` / `remotePort` | 第三方服务器地址和端口。默认 `example.com:888` |
| `listenPort` | 本机监听端口，客户端填这个 |
| `recordOwnChat` | 默认 `false`。你自己的发言由服务器广播回来，已经记下了。万一某个服务器不回显自己的消息，改成 `true` 补记（会自动去重，不会重复）。 |

观战端用 `observer.json`：

```json
{
  "host": "example.com",
  "port": 888,
  "room": "朋友的房",
  "name": "观战记录",
  "version": 4962
}
```

| 字段 | 说明 |
|---|---|
| `host` / `port` | 第三方服务器地址和端口。默认 `example.com:888` |
| `room` | 房间名。必须和房主那边看到的**完全一致**，带密码写成 `房间名$密码` |
| `name` | 观战用的昵称。服务器要求非空；服务器开了 `display_watchers` 时房主那边会看到 |
| `version` | 协议版本号。填错会自动纠正并改写这里 |

## 面向维护者

### 抓的是什么

客户端用**裸 TCP 明文**（libevent `bufferevent`，`ygopro/gframe/duelclient.cpp:84`），
无加密无 WebSocket。帧格式：

```
uint16 LE  长度（= 1 + 载荷长度）
uint8      类型
uint8[]    载荷
```

`proxy.js` 的 `makeSplitter()` 负责切帧。**TCP 不保证一次 `data` 事件正好是一个完整包**，
所以它内部攒着一个尾巴，切不完就留到下一块——这是唯一容易写错的地方，测试里专门覆盖了。

**只解析这几个包，其余一律原样转发：**

| 方向 | 值 | 名称 | 载荷 |
|---|---|---|---|
| 客户端 | `0x10` | `CTOS_PLAYER_INFO` | `uint16 name[20]` |
| 客户端 | `0x16` | `CTOS_CHAT` | UTF-16LE 文本（**不带** player_type） |
| 服务器 | `0x13` | `STOC_TYPE_CHANGE` | `uint8 type`，`座位 = type & 0xf` |
| 服务器 | `0x19` | `STOC_CHAT` | `uint16 player_type` + UTF-16LE 文本 |
| 服务器 | `0x20` | `STOC_HS_PLAYER_ENTER` | 41 字节：`uint16 name[20]` + `uint8 pos` |
| 服务器 | `0x21` | `STOC_HS_PLAYER_CHANGE` | `uint8 status`，`pos = status>>4`，`state = status&0xf` |

座位名靠 `0x20` 建立映射。注意 `player_type` 在线上是 **uint16**，写进 `.yrp3d` 时
扩成 uint32（值不变），这样 `chat-extractor.html` 里现成的
`0/1 = 座位`、`7 = 观战者`、`8 = Tip`、`≥10 = 服务器` 分类直接生效。

### 输出

连接建立就开文件，边收边追加（中途崩了不会全丢）：

- 座位表变化 → 写一个 `sibyl_name`（235）包，槽位布局 `[P0,'---',P0,P1,'---',P1] + uint32 计数`
- 每条对话 → 追加一个 `sibyl_chat`（230）包：`uint32 player_type + UTF-16LE + NUL`

> 会写**多个** 235 包（换座 / 观战者进出都要重写）。提取器的 `readNameSlots()`
> 已经改成**只认最后一个**，所以这是安全的——不是的话座位号会错位。

### 观战端（`observer.js`）

它把 `proxy.js` 当库用：`makeSplitter` 切帧、`Session` 认座位和对话、`Recorder` 落盘。
自己只多做三件事——**发握手包、让座、学版本号**。

加入房间的握手（抄的真人客户端 `ygopro/gframe/duelclient.cpp:147-201`）：

| 顺序 | 包 | 载荷 |
|---|---|---|
| 1 | `CTOS_PLAYER_INFO` `0x10` | `uint16 name[20]`，40 字节 |
| 2 | `CTOS_JOIN_GAME` `0x12` | 48 字节：`uint16 version` + 2 填充 + `uint32 gameid=0` + `uint16 pass[20]` |
| 3 | `CTOS_HS_TOOBSERVER` `0x21` | 无载荷 |

第 3 步**不能一上来就发**：

- 协议上只有 `gameid = 0` 一条路（真人客户端也是，`duelclient.cpp:196`），房间是靠
  `pass` 字段选的，所以必然先以**玩家**身份进去、占用一个座位
- srvpro 的 `HS_TOOBSERVER` 处理器要读 `client.rid`（`ygopro-server.coffee:2992`），
  那是 `join_player` 里才赋值的（`:1949`），发早了房间还不认得你
- 房间已经开打 / 满员时会走 `join_post_watch`，**本来就是观战者**，再发一次没有意义

所以触发条件是「收到 `STOC_TYPE_CHANGE` 且座位号 < 4」——那说明服务器确实把
我们当玩家坐下了。内核在玩家进场时必发这个包（`single_duel.cpp:148-149`），
`ToObserver()` 里也发（`:348-351`）。没收到就不发，宁可不切也不乱发。

> `0x21` 两个方向含义不同：服务器发的是 `HS_PLAYER_CHANGE`（座位状态），
> 客户端发的才是 `HS_TOOBSERVER`（我要观战）。看方向，别看数值。

**版本自动学习**：`version` 填错时服务器回 `STOC_ERROR_MSG`（`0x02`，
`uint8 msg` + 3 填充 + `uint32 code`），`msg == 4` 就表示版本不符、`code` 是它要的版本。
学到之后改写 `observer.json` 重连一次，且只重连一次。

**不自动重连**：房主关房间后重连会让服务器 `ROOM_find_or_create_by_name`
新建一个空房间（`ygopro-server.coffee:764`），越连越乱。

### 界面（`gui.js` + `gui.html`）

浏览器**开不了 TCP 连接**（网页里没有这个 API），所以界面本身干不了活。
做法是起一个**只监听 `127.0.0.1`** 的小 HTTP 服务，浏览器当界面，
真正连服务器的事交给 **spawn 出来的子进程**——就是上面那两个命令行程序，
一行都没改。

**为什么是子进程而不是 `require` 进来跑：**

| 坑 | 说明 |
|---|---|
| `process.exit(1)` | `proxy.js` 端口被占用时直接杀**整个进程**，in-process 会连界面一起带走 |
| `ask()` 挂死 | 配置读不出来时它们会走 readline 提问；stdin 关了就是一个永远卡住、一行输出都没有的僵尸进程 |
| 没有 stop 句柄 | `proxy.js` 的 `start()` 只返回 `net.Server`，活动连接拿不到，停不掉 |

spawn 之后这些都是子进程自己的事。代价是停止只能是 `child.kill()`，
Windows 上那是 `TerminateProcess`（**硬杀**，实测 SIGINT/SIGTERM 处理器根本不会执行）。
录像不会因此丢——`Recorder.write` 用的是 `fs.writeSync`，每个包当场落盘。
但**收尾那行日志不会到**，所以界面上「已停止」一律以 `exit` 事件为准，不解析日志。

**三个必须记住的点：**

1. **`child.stdout.setEncoding("utf8")` 不能省。** 管道里一个中文字可能横跨两个
   chunk，逐块 `toString()` 会把字符**永久撕碎**。
2. **尾部残包容忍。** 录制中读、或者被硬杀之后，文件尾必然是半个包，而解析器见到
   半截包会把**整份**判成已损坏、对话列表直接空掉。所以 `/api/recording` 先自己走
   一遍 5 字节头、停在最后一个完整包，再交给解析器，并回一个 `trimmed: true`。
3. **XSS。** 聊天内容来自别的玩家，一律 `textContent` 渲染。这个页面握着 token，
   能改服务器地址、能起进程——页面里唯一用到 `innerHTML` 的地方是搜索高亮，
   两边都过了转义。

**SSE 只放诊断日志**（`/api/events`），不去从 stdout 里猜哪行是对话——玩家名字里
就可能带 `": "`，猜不准。**对话一律来自轮询 `.yrp3d`**，这样「实时看」和「回看录像」
复用同一个组件，只是指向的文件不同。

**`GET /parser.js`：把解析块发给浏览器。** 拖进来的文件**在浏览器里解析，一个字节都
不上传**，靠的就是这个路由。两个原因不能走服务端：

1. `readBody` 上限 1MB，而真实的 `.yrp3d` 内嵌一整局回放（包类型 231），很容易超；
2. 上传意味着要落盘、要清理，还要重新面对「用文件名拼路径」那套。

发下去的就是 `chat-extractor.html` 里那份哨兵块，由 `_parser.js` 的 `browserSource()`
包成 IIFE（不能裸发，理由见 `_parser.js` 里的注释）。失败时返回 500 而不是空脚本——
空脚本会让界面**静默地**解析不出任何东西。

**导出：** 服务端的录像走 `/api/recording` 取回后用 `normalizeServer()` 归一化，本机文件
用 `extract()` 的结果，两者形状一致，之后走同一组构建函数交给浏览器落盘。
所以**勾选里可以混着两种来源**。`trimmed` / `running` 只给界面提示用，不进导出文件。

**这个页面的 XSS 纪律：** `gui.html` 里 `.innerHTML` **恰好只有 1 处**（搜索高亮，
两边都过了 `esc()`），别处一律 `el()`（内部强制 `textContent`）。`_test_gui.mjs` 静态
断言了这个计数——照着 `chat-extractor.html` 的 toast 抄会一口气加 4 个注入点。

`YRP_DATA_DIR` 环境变量能把配置和录像目录整体挪走（默认是脚本所在目录）。
界面和它 spawn 的子进程都认这个变量——测试就是靠它跑在临时目录里，
**不碰**你真实的 `config.json` / `observer.json` / `replays/`。

### 启动器（`START.vbs`）为什么是 VBS

**因为要没有黑窗口。** Windows 会给「控制台子系统」的程序配一个控制台窗口，
`node.exe` 就是这种程序——跟你怎么启动它、是不是双击 bat 都无关。
而 `wscript.exe` 本身是「GUI 子系统」的，由它去 `Run` 一行命令，node 就分不到窗口了。
（electron 的 exe 没黑窗口也是同一个道理：它是 GUI 子系统。区别只是打包一份
Chromium 要 250 MB，而这里借的是 Windows 自带的 wscript。）

去掉窗口就得补上原本由窗口承担的两件事，这也是这个文件里仅有的两处复杂度：

1. **报错没了地方看** → 输出重定向到临时日志，`rc <> 0` 时弹窗显示末尾一段，
   并留一份 `gui-error.log`。**日志必须每次用新的临时文件**：写固定名字的话，
   「界面已经在跑了」的那一次会因为前一个进程还占着这个文件而重定向失败，
   cmd 在启动 node 之前就报错退出——用户会看到一次莫名其妙的失败弹窗。
2. **中文会变乱码** → node 输出的是 UTF-8，而 FSO 的 `OpenTextFile` 只能按
   ANSI 或 UTF-16 读。必须走 `ADODB.Stream` + `charset=utf-8`。这条实测踩过：
   按默认方式读，弹窗里的中文报错全是乱码。

`.vbs` 用 **UTF-16LE + BOM** 存（文件里有中文，WSH 默认按系统代码页解，UTF-8 会乱）。

**退出**没有窗口可关，所以是页面右上角的按钮 → `POST /api/quit`（`gui.js:572`）：
先 `killAll()` 带走子进程，等响应发完再 `process.exit(0)`——顺序反了浏览器那边
只会看到连接被掐断。

**「双击第二次 = 重新打开页面」** 靠 `probeExisting()`：启动时先读
`gui-url.txt`，拿同一个 token 去打 `/api/state`，200 就说明那个界面还活着，
于是只开浏览器、自己退出。地址文件是明文的，所以**只认 `127.0.0.1`**，
免得被改成别的机器、变成浏览器带着 token 去打外网。
点了「退出界面」会把地址文件删掉，这样下次启动是重新起，而不是去探一个死地址。

### 要出成品（封装成 exe）

四个启动器都优先用同目录的 `yrp.exe`，所以**打包不会改动开发时的用法**——
在源码树里它们照旧走 `node`。封装细节见 [`../PACKAGING.md`](../PACKAGING.md)：

```bash
cd ..                  # 回到 yrp-tools/
node build-release.mjs          # → release/yrp-tools-<日期>/
node _test_bundle.mjs  # 打包器快测（不用 postject）
node _test_sea.mjs     # 真打 exe 冒烟，慢
```

> ⚠️ `gui.html` 和 `chat-extractor.html` 是**烘进 exe** 的。改完必须重新打包才会生效，
> 光把文件拷到发布目录旁边没有任何用。

`_test_gui.mjs` 起真的 `gui.js` 服务和假 srvpro，把整条链路走一遍：
无 token 访问 `/` 和 `/api/*` 都要 401、开始观战、SSE 收到日志、录像出现、
解析出的座位名和说话者分类都对、停止后状态回到未运行。
另外单独测**把录像砍掉 3 字节**之后仍然解析成功且 `trimmed: true`（丢的只能是
尾部那一条），以及 `?name=..\..\config.json` 被拒。

导出那一段用**真的 `/api/recording` 响应**喂 `normalizeServer()` + 构建函数，
和 `_test_parser.mjs` 一样的黄金字符串。⚠️ 但**不能**拿这个截断文件和
`chat-extractor.html` 的结果逐字节比对：`chat-extractor.html` 直接读文件，尾部半个包会让它
整份判成损坏（`ok:false`），而界面先 `trimToLastPacket` 所以这边是 `ok:true`。
**这是有意的差异**，别去「修」它。

还有两条静态断言盯着 `gui.html`：`.innerHTML` 恰好 1 处（多一个就是多一个注入点），
以及 token 占位符恰好 1 处——`gui.js` 只替换**第一处**，多出来的那处要是排在前面
（比如被写进注释），被替换的就成了注释，页面拿到的是字面量，所有接口 401。

**退出**那一段只能对着**子进程**测：`/api/quit` 走的是 `process.exit`，
在测试进程里调会把跑测试的进程自己杀掉。所以它 spawn 一个真的 `gui.js`，
起一个观战子进程，点退出，然后断言 `gui.js` 自己退了（退出码 0）、
地址文件被删了、端口能马上重新监听。

`_test_observer.mjs` 里的假 srvpro 按真实协议回包（先 `JOIN_GAME` 再
`TYPE_CHANGE`，收到让座包再回座位表和对话），最后把产出的 `.yrp3d` 喂进
`../chat-extractor.html` 里那份真解析器——和 `_test_proxy.mjs` 同一个验收标准。

改了 `proxy.js`、`observer.js`、`gui.js`、`gui.html` 或 `chat-extractor.html` 都要跑一遍。
`gui.html` 是零构建的（没有打包步骤），改完**刷新页面**就生效；
`chat-extractor.html` 的哨兵块改动要**重启界面**——`/parser.js` 是模块加载时算一次并带
`no-store` 下发的，不重启界面还会发旧的。

### 改 `proxy.bat` / `observer.bat` / `gui-console.bat` 前先看这里

**先看 exe 再看 node**，这个顺序不能反：三个 `.bat` 现在都是
`if exist "yrp.exe" → goto useexe` 排在 `where node` **前面**。反过来的话，
**没装 Node 的机器会先撞上「请先安装 Node.js」那个分支就 exit 了**，
永远走不到旁边那个 exe —— 正好把要解决的场景挡死。
`_test_sea.mjs` 静态断言了这个顺序。

三个 `.bat` 还必须**各自显式传 `--role=`**（`proxy` / `observer` / `gui`）：
exe 里三个入口是同一份代码，不传角色就一律当界面起。
`START.vbs` 同理，只是走的是「同目录有 exe 就用 exe」。

这三个文件另有一条硬约束，破坏之后会**双击后窗口一闪就没**：

1. **必须 CRLF 换行。** cmd.exe 解析批处理依赖 CRLF；LF-only 的文件会让它把多行
   结构拆错。用 Git Bash / 各种编辑器保存时注意别退化成 LF。
2. **必须纯 ASCII，一个中文字都不能有。** `chcp 65001` 会在 cmd 逐行读文件的过程中
   换掉代码页，cmd 用旧代码页算出的偏移去续读，**多字节字符会让它从行中间接着解析**
   ——实测第一行正常输出，紧接着就把 `echo` 的尾巴 `ho` 和上一行的句尾 `，句号。`
   当成命令去执行。所有中文都由 node 打印，那里没有这个问题。

同理，`>nul` 这三个字符要原样保留（别写成 `>/dev/null`，Windows 上那是无效路径，
cmd 会报「系统找不到指定的路径」）。这文件里没有任何需要转义的东西，正常编辑即可。
