# 对话记录

**在第三方服务器上打牌 / 观战，把对局对话录下来。**

这个目录里有**两个**工具，解决同一件事的两种做法：

| | 怎么用 | 适合 |
|---|---|---|
| **代理** | 把客户端的服务器地址改成 `127.0.0.1`，你在自己电脑上正常打牌 | **自己下场打**——你自己说的话也只有这样才录得到 |
| **观战** | 电脑上**不用开客户端**，填个服务器 + 房间名就挂着录 | **盯别人的局**——开着电脑挂机，不占你的客户端 |

两个输出的都是 `.yrp3d`。用窗口的话查看和导出都在里面；命令行版拖进 `../chat-extractor.html`。

> **服务器地址已经填好了。** 窗口里的「服务器地址 / 端口」预填的就是
> `example.com:888`，命令行版第一次问的时候括号里也是它，直接回车即可。
> 要连别的服务器就把它覆盖掉 —— 三个地方（`proxy.js` / `observer.js` / `api.js`）
> 各有一份默认值，`_test_api.mjs` 会断言它们一致，改的时候别漏。

**开哪个**——推荐从窗口进，两种模式都在里面：

| 开哪个 | 是什么 | 适合 |
|---|---|---|
| **`yrp-tools.exe`** | 独立窗口，点按钮，**录完直接在里面看对话** | **推荐**（打包后才有） |
| `gui-console.bat` | 同一个窗口，但**留着控制台窗口**显示日志 | 双击了没反应时用它看报错 |
| `node proxy.js` | 命令行版代理 | 想要一个能一直开着的窗口 |
| `node observer.js` | 命令行版观战 | 同上 |

窗口只是**替你把这两个命令行程序开起来**（子进程），功能完全一样，
录出来的文件也一样。命令行版不会因为有了窗口就被砍掉。

> 观战端只**看**：发完进房间的握手包之后就不再说话了，也不会占用玩家座位——
> 它先按普通玩家进去（协议上没别的办法），一发现自己被安排到座位上就立刻
> 发切换观战，和真人点「观战」是同一套动作。观战者不受服务器心跳约束，可以一直挂。

## 模式零：窗口（推荐）

> **前置要求：打包好的 `yrp-tools.exe` —— 或者装了 Node.js 的开发树。**
> 这个目录**全部**都跑在 Node 上：录制要靠它开 TCP（网页里没有这个 API），
> 窗口是 Electron 起的一个独立进程，界面和录制逻辑同在一条 IPC 上，**不经过网络**。
>
> 开发时用 `npx electron .` 起（需要 `npm install`；`electron` 是唯一的重依赖），
> 或者双击 `gui-console.bat`。要拷给别人就 `npm run dist` 打成一个**安装包**，
> 见 [`../PACKAGING.md`](../PACKAGING.md)；对方拿到**什么都不用装**，双击装一下就行。
>
> 只想给「看录像 + 导出」的话，给 `../chat-extractor.html` 那**一个文件**就行，
> 双击即用、自包含，导出结果和窗口里逐字节一致（同一份代码）。

双击 **`yrp-tools.exe`**（开发树里是 `npx electron .`），开出一个**独立窗口**。
两种模式在里面各是一个标签页，点「开始记录」就行，**录完直接在窗口下面看对话**。

```
┌ 观战记录 │ 自己打牌（代理） ┐
│  服务器地址 / 端口 / 房间名 / 昵称   [开始记录] [停止]  ● 记录中
│  ── 实时日志（诊断用）──
│  ...
│  ── 录像（每 2 秒刷新）──
│  把 .yrp3d 文件或整个文件夹拖到这里 —— 也可以 [选择文件…] [选择文件夹…]
│  [全选] [全不选] 已勾 2 个      ☐排除系统消息 ☐排除观战发言
│  [合并 TXT] [分文件 TXT] [JSON] [CSV] [复制全部]
│  [📁 导出目录…] 导出到：下载
│  ☑ 示例房-09-25「16：57：48」.yrp3d        录制中  1.6 KB
│  ☑ 09-25「13：09：46」.yrp3d                        2.1 KB
│  ☐ 本机.yrp3d  本机                                 3.4 KB
│  ── 对话 · 09-25「13：09：46」.yrp3d ──  [搜索……] [全部消息 ▾]
│  小明      :: 你好
│  观战者    :: 围观一下
└──────────────────────────────┘
```

**日志和对话是两回事**：上面那块日志只是给你看程序在干什么（连上没有、让座没有）；
下面那块对话是从 `.yrp3d` 文件里**解析出来的**，名字、说话者身份都以文件为准。
所以正在录的时候它每 2 秒重读一遍最新那个文件——看到的就是实时对话。

### 导出

左边每个录像前面的**方框勾上**，就能一起导出。四种格式：

| 按钮 | 产出 |
|---|---|
| **合并 TXT** | 一个文件，每个录像一段，段落头是 `### 文件名` |
| **分文件 TXT** | 每个录像一个 `.txt`，文件名是 `原名_chat_<时间戳>.txt` |
| **JSON** | 一个文件，每个录像一条记录（含偏移、说话者类型、座位） |
| **CSV** | 一个文件，Excel 能直接开。带 UTF-8 BOM，中文不会变乱码 |
| **复制全部** | 和「合并 TXT」同样的内容，直接进剪贴板，不落盘 |

两个勾选框（**排除系统消息** / **排除观战发言**）对**上面每一种**都生效，
「复制全部」也一样。只想看双方玩家说的话就两个都勾上。

**文件名都带导出时间**（`录像对话汇总_20260925-143012.txt`），所以重复导出不会覆盖上一次。
同一次「分文件 TXT」里的所有文件**共用一个时间戳**，方便认出是同一批。

导出完成右下角会弹一个提示，写明导出了几个、存到哪了，**文件名能点**——
点一下用系统默认程序打开**真正落盘的那个文件**。

#### 导出到哪里

默认落在**「下载」文件夹**。想固定位置就点 **「📁 导出目录…」** 选个文件夹，
之后所有导出都进那里。那一行提示一直写着当前目标。

窗口里这是系统**原生**的目录选择框，任何 Windows 上都能用，
也不会问「是否允许下载多个文件」——一次导出多少个都照样落盘。

### 把本机的录像拖进来

不光是刚录的，**你以前用别的工具存下的 `.yrp3d` 也能一起处理**：

- 把文件（或整个文件夹）**拖到录像面板上**，也可以点「选择文件…」「选择文件夹…」
- 拖进来的排在列表最前面，带一个「本机」标记
- 可以和服务器上录的那些**一起勾、一起导出**

> 这些文件**只在窗口里解析，一个字节都不上传**——所以多大的文件都行，
> 也不会在服务器上留下副本。代价是**按 Ctrl+R 重载就没了**（服务器上的录像不受影响），
> 想清掉就点「清空拖入的文件」。
>
> 顺带一提，这也是为什么拖进来的文件解析得比服务器上的快：不用走网络，也不用落盘。

| 要干什么 | 怎么做 |
|---|---|
| 停止录像 | 点「停止」。窗口留着，可以接着录下一局 |
| **退出整个程序** | **点窗口右上角的 ×**。正在录的话会先问你一句「退出会停掉录制」 |
| 想接着录 | 上面那个确认框里点「继续录制」，什么都不会变 |
| 再双击一次 exe | 不会开出第二个窗口，而是把已经开着的那个**提到前面来** |
| 双击了没反应 | 改用 `gui-console.bat`，报错会留在控制台窗口里 |

> **退出不需要去别的地方点按钮。** 窗口就是程序，关掉窗口 = 程序退出 +
> 后台的录制脚本一起收摊。这一点和以前那套「浏览器标签页 + 回页面点退出界面」
> 是最大的区别 —— 标签页关掉时进程还活着，窗口关掉时进程就没了。

**窗口是独立的，不开浏览器、也不开黑窗口。** 双击 exe 就是全部动作。

**出错了看哪里**：启动失败会直接弹一个窗；想看更细的就用 `gui-console.bat`，
主进程的日志和子进程的输出都在那个控制台里。窗口里的「实时日志」面板则只显示
录制子进程说了什么（连上没有、让座没有）。

## 模式一：代理（自己打牌）

**为什么需要它**

标准 ygopro 客户端打牌时存的 `.yrp` 录像**只记录操作**（出了哪张卡、点了哪个按钮），
**不记录对话**。对话虽然在网络上传了，但没进录像文件，事后补不回来。

服务器也不是你能改的——所以只剩一个办法：**在自己的客户端和服务器之间插一个中转**。

```
ygopro 客户端 ──► 127.0.0.1:<本机端口> ──► 第三方服务器
                        │
                        └─► replays/09-25「14：32：42」.yrp3d
                                  │
                                  └─► 窗口里勾选导出（命令行版则拖进 ../chat-extractor.html）
```

代理只**看**不改：转发过去的字节和客户端发来的完全一样，对局本身不受影响。
它抓的是**你自己电脑上自己的客户端**的流量，不碰服务器。

录下来的文件是 `.yrp3d` 格式，**窗口里可以直接查看和导出**——搜索、筛选观战发言、
排除系统消息、批量导出那一整套都在。命令行版没有窗口，把 `replays/` 里的文件拖进
`../chat-extractor.html` 即可，两边行为一致（导出格式是同一份代码，见
[../README.md](../README.md#共享的解析块改代码前必读)）。

---

### 三步走

#### 1. 双击 `yrp-tools.exe`，选「自己打牌（代理）」那一页，点「开始记录」

命令行版则是 `node proxy.js`。第一次运行会问你三件事（括号里是默认值，直接回车就是它）：

第一次运行会问你三件事（括号里是默认值，直接回车就是它）：

```
第三方服务器地址（域名或 IP）（回车 = example.com）: example.com
第三方服务器端口（回车 = 888）: 888
本机监听端口（客户端等一会儿要连这个）（回车 = 888）: 888
```

就是你平时在客户端里填的那个地址和端口。填完记在 `config.json` 里，以后不再问。

> 「本机监听端口」保持和服务器端口一样就行。只有当系统提示端口被占用时才需要改。

#### 2. 客户端改成连本机

打开 ygopro，把服务器地址改成 **`127.0.0.1`**，端口改成**上面第三步填的那个**。

然后正常打牌 / 观战。代理窗口会实时打印它收到的东西：

```
[14:32:42] 已连上 example.com:888
[14:32:47] 我的昵称：RLX
[14:33:01] RLX: 你好
[14:33:05] 新人: 你好啊
[14:33:12] 观战者: 围观
[14:35:20] 断开：09-25「14：32：42」.yrp3d —— 3 条对话，245 字节
```

#### 3. 打完看对话

用窗口的话，`录像` 面板里点一下文件就能看，勾上就能导出（见上面的「导出」一节）。
命令行版去 `proxy/replays/` 把 `.yrp3d` 拖进 `../chat-extractor.html`，跟平时用录像一样。

## 模式二：观战（盯别人的局）

**电脑上不用开客户端。** 窗口里选「观战记录」那一页点「开始记录」，
或命令行 `node observer.js`。第一次运行问你四件事（同样，括号里是默认值）：

```
第三方服务器地址（域名或 IP）（回车 = example.com）: example.com
第三方服务器端口（回车 = 888）: 888
房间名（要和客户端里填的完全一致）: 朋友的房
观战用的昵称（服务器要一个名字）: 观战记录
```

然后它就自己连上去、进房间、静默录对话：

```
[14:32:42] 已连上，正在加入房间…
[14:32:42] 新连接 -> 朋友的房-09-25「14：32：42」.yrp3d
[14:32:43] 占了玩家位，切换到观战…
[14:33:01] 房主: 你好
[14:33:05] 挑战者: 好久不见
[14:40:12] 断开：朋友的房-09-25「14：32：42」.yrp3d —— 2 条对话，318 字节
```

想停就按 **Ctrl+C**，或者直接关窗口。录像在同一个 `replays/` 目录里，
文件名前面带房间名（`朋友的房-09-25「…」.yrp3d`），和代理录的区分得开。

重填配置：`node observer.js --config`。

### ⚠️ 房间名必须完全一致

这是最容易踩的坑。服务器的行为是「**按名字找房间，找不到就新建一个**」
（`ygopro-server.coffee:764`）。所以房间名打错一个字母，它不会报错，
而是**给你开一个没人进的空房间**，你就对着空房间录半天。

程序 20 秒后如果还没见到玩家或对话，会打印一条提醒。真遇到了就核对
`observer.json` 里的 `room`：

- **区分大小写**
- **带密码的房间**要写成 `房间名$密码`（`$` 是服务器约定的分隔符）
- 最长 19 个字，超了会被截断（窗口里填的话会当场提醒）

### 版本号会自动学

不同服务器的版本号可能不一样（服务器配置里一个数字，客户端源码里另一个）。
填错不用管：服务器会把正确版本告诉你，程序自动改写 `observer.json` 再连一次。

### 房主关房间后不会自动重连

故意的。房主一走，重连只会让服务器给你**新建一个空房间**。要接着盯就再跑一次。

## 常见问题

**打不开 / 连不上服务器**

代理窗口会打印 `连不上 xxx:888 —— ...`。检查 `config.json` 里的地址和端口是不是填错了。
确认没问题就再跑一次 `node proxy.js --config` 重填。

**提示端口被占用**

说明已经开着一个代理了，或者别的程序占了 888。用 `--config` 把「本机监听端口」改成
别的（比如 889），然后记得客户端那边也要跟着改。

**录像里只有系统消息，没有玩家说的话**

先确认说话的时候代理窗口有没有跟着打印。没有的话说明对话走的是别的通道，把
`replays/_dump_*.log`（见下）发出来看看。

**观战者没有名字**

和 `.yrp3d` 录像一样：这个格式里观战发言只有内容、没有名字，多个观战者同时说话分不出来。
只有服务器开了 `display_watchers` 才带名字，那时会显示成 `观战者「名字」`。

**打完发现生成好几个文件**

一个 TCP 连接一个文件。掉线重连、或者客户端重开，就会多一个。这是正常的。

**观战连不上 / 录不到**

先看窗口里有没有 `连不上 xxx:888 —— ...`（地址端口错）。
没有的话跑 `node observer.js --dump`，它会把收到的每个包倒进
`replays/_dump_*.log`，断开时还会打印包类型统计——正常至少该有 `0x20`（座位）。
一条都没有就是根本没进到房间里，多半是房间名不对（见上面的警告）。

**标签决斗（2v2）**

座位 2、3 的名字解析不出来，他们的发言会显示成 `系统2` / `系统3`。这条暂时没做。

## 诊断模式

如果收到的对话不对劲（或者一条都没有），跑：

```bash
node proxy.js --dump
```

界面上勾「诊断模式」再点开始，效果一样。

它会把**每一个包**的类型、长度、十六进制倒进 `replays/_dump_*.log`。
断开连接时控制台还会打印这次见到的包类型统计：

```
见到的包类型：0x01×40 0x13×1 0x16×3 0x19×3 0x20×2 0x21×3
```

正常的话应该能看到 `0x19`（对话）和 `0x20`（座位名字）。
一个 `0x19` 都没有，就是服务器没走标准协议。

## 配置项

代理用 `config.json`：

```json
{
  "remoteHost": "example.com",
  "remotePort": 888,
  "listenPort": 888,
  "recordOwnChat": false
}
```

| 字段 | 说明 |
|---|---|
| `remoteHost` / `remotePort` | 第三方服务器地址和端口。默认 `example.com:888` |
| `listenPort` | 本机监听端口，客户端填这个 |
| `recordOwnChat` | 默认 `false`。你自己的发言由服务器广播回来，已经记下了。万一某个服务器不回显自己的消息，改成 `true` 补记（会自动去重，不会重复）。 |

观战端用 `observer.json`：

```json
{
  "host": "example.com",
  "port": 888,
  "room": "朋友的房",
  "name": "观战记录",
  "version": 4962
}
```

| 字段 | 说明 |
|---|---|
| `host` / `port` | 第三方服务器地址和端口。默认 `example.com:888` |
| `room` | 房间名。必须和房主那边看到的**完全一致**，带密码写成 `房间名$密码` |
| `name` | 观战用的昵称。服务器要求非空；服务器开了 `display_watchers` 时房主那边会看到 |
| `version` | 协议版本号。填错会自动纠正并改写这里 |

## 面向维护者

### 抓的是什么

客户端用**裸 TCP 明文**（libevent `bufferevent`，`ygopro/gframe/duelclient.cpp:84`），
无加密无 WebSocket。帧格式：

```
uint16 LE  长度（= 1 + 载荷长度）
uint8      类型
uint8[]    载荷
```

`proxy.js` 的 `makeSplitter()` 负责切帧。**TCP 不保证一次 `data` 事件正好是一个完整包**，
所以它内部攒着一个尾巴，切不完就留到下一块——这是唯一容易写错的地方，测试里专门覆盖了。

**只解析这几个包，其余一律原样转发：**

| 方向 | 值 | 名称 | 载荷 |
|---|---|---|---|
| 客户端 | `0x10` | `CTOS_PLAYER_INFO` | `uint16 name[20]` |
| 客户端 | `0x16` | `CTOS_CHAT` | UTF-16LE 文本（**不带** player_type） |
| 服务器 | `0x13` | `STOC_TYPE_CHANGE` | `uint8 type`，`座位 = type & 0xf` |
| 服务器 | `0x19` | `STOC_CHAT` | `uint16 player_type` + UTF-16LE 文本 |
| 服务器 | `0x20` | `STOC_HS_PLAYER_ENTER` | 41 字节：`uint16 name[20]` + `uint8 pos` |
| 服务器 | `0x21` | `STOC_HS_PLAYER_CHANGE` | `uint8 status`，`pos = status>>4`，`state = status&0xf` |

座位名靠 `0x20` 建立映射。注意 `player_type` 在线上是 **uint16**，写进 `.yrp3d` 时
扩成 uint32（值不变），这样 `chat-extractor.html` 里现成的
`0/1 = 座位`、`7 = 观战者`、`8 = Tip`、`≥10 = 服务器` 分类直接生效。

### 输出

连接建立就开文件，边收边追加（中途崩了不会全丢）：

- 座位表变化 → 写一个 `sibyl_name`（235）包，槽位布局 `[P0,'---',P0,P1,'---',P1] + uint32 计数`
- 每条对话 → 追加一个 `sibyl_chat`（230）包：`uint32 player_type + UTF-16LE + NUL`

> 会写**多个** 235 包（换座 / 观战者进出都要重写）。提取器的 `readNameSlots()`
> 已经改成**只认最后一个**，所以这是安全的——不是的话座位号会错位。

### 观战端（`observer.js`）

它把 `proxy.js` 当库用：`makeSplitter` 切帧、`Session` 认座位和对话、`Recorder` 落盘。
自己只多做三件事——**发握手包、让座、学版本号**。

加入房间的握手（抄的真人客户端 `ygopro/gframe/duelclient.cpp:147-201`）：

| 顺序 | 包 | 载荷 |
|---|---|---|
| 1 | `CTOS_PLAYER_INFO` `0x10` | `uint16 name[20]`，40 字节 |
| 2 | `CTOS_JOIN_GAME` `0x12` | 48 字节：`uint16 version` + 2 填充 + `uint32 gameid=0` + `uint16 pass[20]` |
| 3 | `CTOS_HS_TOOBSERVER` `0x21` | 无载荷 |

第 3 步**不能一上来就发**：

- 协议上只有 `gameid = 0` 一条路（真人客户端也是，`duelclient.cpp:196`），房间是靠
  `pass` 字段选的，所以必然先以**玩家**身份进去、占用一个座位
- srvpro 的 `HS_TOOBSERVER` 处理器要读 `client.rid`（`ygopro-server.coffee:2992`），
  那是 `join_player` 里才赋值的（`:1949`），发早了房间还不认得你
- 房间已经开打 / 满员时会走 `join_post_watch`，**本来就是观战者**，再发一次没有意义

所以触发条件是「收到 `STOC_TYPE_CHANGE` 且座位号 < 4」——那说明服务器确实把
我们当玩家坐下了。内核在玩家进场时必发这个包（`single_duel.cpp:148-149`），
`ToObserver()` 里也发（`:348-351`）。没收到就不发，宁可不切也不乱发。

> `0x21` 两个方向含义不同：服务器发的是 `HS_PLAYER_CHANGE`（座位状态），
> 客户端发的才是 `HS_TOOBSERVER`（我要观战）。看方向，别看数值。

**版本自动学习**：`version` 填错时服务器回 `STOC_ERROR_MSG`（`0x02`，
`uint8 msg` + 3 填充 + `uint32 code`），`msg == 4` 就表示版本不符、`code` 是它要的版本。
学到之后改写 `observer.json` 重连一次，且只重连一次。

**不自动重连**：房主关房间后重连会让服务器 `ROOM_find_or_create_by_name`
新建一个空房间（`ygopro-server.coffee:764`），越连越乱。

### 窗口（`main.js` + `preload.js` + `api.js` + `gui.html`）

网页**开不了 TCP 连接**（网页里没有这个 API），所以页面本身干不了活。
做法是把真正连服务器的事交给 **spawn 出来的子进程**——就是上面那两个命令行程序，
一行都没改。

三层分工，`api.js` 是中间那层：

| 文件 | 干什么 | 有没有 Electron |
|---|---|---|
| `main.js` | 开窗口、单实例锁、数据落在哪、关窗时收摊、把系统能力注入进去 | 有 |
| `api.js` | 读配置、起停子进程、解析录像、导出、提文件夹 | **没有**（所以能脱离 Electron 测） |
| `gui.html` | 那张页面。`window.yrp.invoke(通道)` 进、`window.yrp.on("yrp:event")` 出 | 没有 |

`preload.js` 是两者之间那道口子，只放行 `invoke` / `on` 两个函数，
**不暴露 `ipcRenderer` 本体，也不暴露事件对象**。

**为什么是子进程而不是 `require` 进来跑：**

| 坑 | 说明 |
|---|---|
| `process.exit(1)` | `proxy.js` 端口被占用时直接杀**整个进程**，in-process 会连窗口一起带走 |
| `ask()` 挂死 | 配置读不出来时它们会走 readline 提问；stdin 关了就是一个永远卡住、一行输出都没有的僵尸进程 |
| 没有 stop 句柄 | `proxy.js` 的 `start()` 只返回 `net.Server`，活动连接拿不到，停不掉 |

spawn 之后这些都是子进程自己的事。代价是停止只能是 `child.kill()`，
Windows 上那是 `TerminateProcess`（**硬杀**，实测 SIGINT/SIGTERM 处理器根本不会执行）。
录像不会因此丢——`Recorder.write` 用的是 `fs.writeSync`，每个包当场落盘。
但**收尾那行日志不会到**，所以界面上「已停止」一律以 `exit` 事件为准，不解析日志。

**四个必须记住的点：**

1. **`child.stdout.setEncoding("utf8")` 不能省。** 管道里一个中文字可能横跨两个
   chunk，逐块 `toString()` 会把字符**永久撕碎**。
2. **子进程要带 `ELECTRON_RUN_AS_NODE=1`。** 打包态和开发态 `process.execPath`
   都是 `electron.exe`，不带这个变量会把 `proxy.js` 当成一个 Electron 应用起，
   弹出一个没有任何内容的 GUI 窗口。
3. **尾部残包容忍。** 录制中读、或者被硬杀之后，文件尾必然是半个包，而解析器见到
   半截包会把**整份**判成已损坏、对话列表直接空掉。所以 `recording:parse` 先自己走
   一遍 5 字节头、停在最后一个完整包，再交给解析器，并回一个 `trimmed: true`。
4. **XSS。** 聊天内容来自别的玩家，一律 `textContent` 渲染。页面能改服务器地址、
   能起进程——`gui.html` 里唯一用到 `innerHTML` 的地方是搜索高亮，两边都过了转义。

**事件通道只放诊断日志**（`yrp:event`），不去从 stdout 里猜哪行是对话——玩家名字里
就可能带 `": "`，猜不准。**对话一律来自轮询 `.yrp3d`**，这样「实时看」和「回看录像」
复用同一个组件，只是指向的文件不同。

**`parser:get`：把解析块发给渲染进程。** 拖进来的文件**在窗口里解析，一个字节都
不上传**，靠的就是它。为什么不在主进程解析：那些字节本来就在渲染进程手里
（`<input>` / 拖放给的 `File`），送到主进程反而要把整份回放（内嵌一局，包类型 231）
拷一遍过去。

发下去的就是 `chat-extractor.html` 里那份哨兵块，由 `_parser.js` 的 `browserSource()`
包成 IIFE（不能裸发，理由见 `_parser.js` 里的注释），渲染进程 `new Function()` 执行。
失败时给出错误而不是空脚本——空脚本会让界面**静默地**解析不出任何东西。

> 这条通道的前身是一个 `GET /parser.js` 路由。当时的第二条理由是「上传要落盘、
> 要清理、还要重新面对用文件名拼路径那套」，第一条则是 HTTP 请求体 1MB 的上限。
> 走 IPC 之后那两条都不存在了，但这个设计留了下来 —— 它本来就更省事。

**导出：** 服务端的录像走 `recording:parse` 取回后用 `normalizeServer()` 归一化，
本机文件用 `extract()` 的结果，两者形状一致，之后走同一组构建函数落盘。
所以**勾选里可以混着两种来源**。`trimmed` / `running` 只给界面提示用，不进导出文件。

**导出的两个约束**（`api.js` 里，`_test_api.mjs` 盯着）：

- **目录必须是主进程自己发出去过的**。渲染进程不该有能力往任意路径写文件 ——
  界面里那些文件名和对话内容都是别人能左右的东西。`exportDirs` 这个 `Set` 就是白名单。
- **一个名字不合法就整批不写**。先全部验完再动手，否则会留下「报了错，但文件夹里
  多了几个文件」这种状态，用户还不知道多了哪些。
- `shell:openFile` 只收**文件名**，绝对路径由主进程拼。

**这个页面的 XSS 纪律：** `gui.html` 里 `.innerHTML` **恰好只有 1 处**（搜索高亮，
两边都过了 `esc()`），别处一律 `el()`（内部强制 `textContent`）。`_test_api.mjs` 静态
断言了这个计数——照着 `chat-extractor.html` 的 toast 抄会一口气加 4 个注入点。

`YRP_DATA_DIR` 环境变量能把配置和录像目录整体挪走（默认是脚本所在目录）。
`api.js` 和它 spawn 的子进程都认这个变量——测试就是靠它跑在临时目录里，
**不碰**你真实的 `config.json` / `observer.json` / `replays/`。

> ⚠️ `api.js` 里那几根路径是**模块加载时**算出来的，所以 `main.js` 必须在
> `require("./api.js")` **之前**把 `process.env.YRP_DATA_DIR` 设好。顺序反了不报错，
> 只会静默用错目录。

### 关窗 = 退出，以及「只能开一个」

**这两件事都是以前那套结构逼出来的麻烦，现在由 Electron 直接提供。**

原来是浏览器标签页：关了标签页进程还活着，得回页面点「退出界面」；为了知道
「界面是不是已经在跑了」，还要写一个地址文件 `gui-url.txt` 再拿 token 去打它探活。
现在：

- **关窗口即退出。** `window-all-closed` → `app.quit()`，另外 `before-quit` /
  `will-quit` / `process.on("exit")` 三条路都调 `api.killAll()` ——
  录制子进程不是 Electron 的 utilityProcess，不会被自动回收，漏一条就留下
  占着端口的孤儿进程。
- **关窗前会问一句**（`main.js` 的 `confirmQuit()`）：正在录就弹「继续录制 / 退出并停止录制」，
  没在录就直接退。**关窗（×）和以后可能加的「退出」按钮共用同一个函数**，
  否则两处问的话不一样，用户会以为踩到了两套逻辑。
- **只能开一个实例** 靠 `app.requestSingleInstanceLock()`：第二个实例让位并
  `app.quit()`，已有的那个收到 `second-instance` 把窗口提回前面。
  两个窗口会抢同一批录像文件，所以只能有一个。

> `killAll()` 单独不足以决定「退不退」：它只是发信号，进程真正消失是在
> 子进程的 `exit` 事件里，那之前 `anyRunning()` 还是 true。所以 `main.js` 里
> 另有一个 `quitting` 标志，否则会退一次问两遍。

### 测试

```bash
node _test_proxy.mjs      # 代理：切帧 / 解码 / 输出能被提取器读
node _test_e2e.mjs        # 代理：假服务器 + 假客户端，字节级透传
node _test_observer.mjs   # 观战：假 srvpro，握手 / 让座 / 版本学习 / 落盘
node _test_api.mjs        # 后端：起停子进程 / 残包 / 路径穿越 / 导出 / 退出清理
node ../_test_parser.mjs  # 提取器本体
```

**这五条都只要 `node xxx.mjs`，不需要装 Electron。** `api.js` 里一行
`require("electron")` 都没有（弹目录 / 剪贴板 / 打开文件全是注入进来的），
所以测它的时候传几个假函数就行。这是抽 `api.js` 出来最主要的收益。

`_test_api.mjs` 起假 srvpro，把整条链路走一遍：开始观战、收到日志事件、录像出现、
解析出的座位名和说话者分类都对、停止后状态回到未运行。
另外单独测**把录像砍掉 3 字节**之后仍然解析成功且 `trimmed: true`（丢的只能是
尾部那一条），以及 `name = ..\..\config.json` 被拒。

导出那一段用**真的 `recording:parse` 响应**喂 `normalizeServer()` + 构建函数，
和 `_test_parser.mjs` 一样的黄金字符串。⚠️ 但**不能**拿这个截断文件和
`chat-extractor.html` 的结果逐字节比对：`chat-extractor.html` 直接读文件，尾部半个包会让它
整份判成损坏（`ok:false`），而这边先 `trimToLastPacket` 所以是 `ok:true`。
**这是有意的差异**，别去「修」它。

页面那条静态断言还在：`.innerHTML` 恰好 1 处（多一个就是多一个注入点），
以及那几个 `id="…"` 必须都在——删按钮漏删绑定的话 `$()` 返回 null，
`null.onclick` 会抛在 `init()` 之前，整个界面一条日志都出不来。

**「退出带走子进程」那一段现在是直接测的。** 以前 `/api/quit` 走 `process.exit`，
在测试进程里调会把自己杀掉，所以只能 spawn 一个真的 `gui.js` 去测。现在
`app:quit` 只收摊、退不退是调用方的事，于是可以在测试进程里起一个观战子进程、
调它、然后断言**那条 TCP 连接断了**（比查进程列表稳，也不会误伤别的 node 进程）。

> 剩下没被自动测到的只有「Electron 的 `before-quit` 确实调了 `killAll`」这一环，
> 那条由 `_test_electron.mjs` 起真程序 + 人肉验收兜底。

`_test_observer.mjs` 里的假 srvpro 按真实协议回包（先 `JOIN_GAME` 再
`TYPE_CHANGE`，收到让座包再回座位表和对话），最后把产出的 `.yrp3d` 喂进
`../chat-extractor.html` 里那份真解析器——和 `_test_proxy.mjs` 同一个验收标准。

改了 `proxy.js`、`observer.js`、`api.js`、`gui.html` 或 `chat-extractor.html` 都要跑一遍。
`gui.html` 是零构建的（没有打包步骤），开发态**按 Ctrl+R 重载**就生效
（日志面板靠 `log:backlog` 灌回来，所以不会是空的）；
但打包态两个 HTML 都在 exe 里，**改完必须重新打包**。

### 还有一条慢的：`../_test_electron.mjs`

它起**真的程序**，走完整条链路，然后**关窗口**。覆盖的是「打包后才可能坏、
平时测不出来」的东西：preload 有没有被带进包、`gui.html` 在不在、
子进程被 spawn 得起来吗（打包态 `process.execPath` 是那个 exe，不是 node）。

```bash
node ../_test_electron.mjs             # 开发态（快）
node ../_test_electron.mjs --packaged  # 先打包再跑，顺带断言没夹带你的数据（慢）
```

判定「关窗之后录制子进程真的死了」用的是**那条 TCP 连接本身**：假 srvpro 跑在
测试进程里，子进程连着它；子进程要是被漏掉了，那条 socket 会一直开着。

> 自检的报告**同时写 stdout 和数据目录里的 `selftest.log`**，测试两条都认。
> 双写的理由：程序要是在 flush 之前崩掉，stdout 里那点输出就没了，
> 看上去像「自检根本没跑」。

### 数据落在哪（开发态和打包态不一样）

| | 数据目录 | 录像默认在 |
|---|---|---|
| 开发态（`npx electron .`） | `proxy/` | `proxy/replays/` |
| **打包态（装了安装包）** | **`%APPDATA%\yrp-tools\`** | `%APPDATA%\yrp-tools\replays\` |

打包态**故意不放安装目录**：NSIS 升级时会先跑旧版卸载器，也就是把安装目录整个删掉
再装新的 —— 数据放那儿的话，用户升一次级丢一次录像，而且是静默的。
见 [`../PACKAGING.md`](../PACKAGING.md) 的「坑 9」。

**录像目录还能改到任意位置**（工具栏「更改…」），换过之后记在同目录的
`settings.json` 里，下次启动照旧。实现上分三步：

```
api.js 读 settings.json 算出 outDir
      → 起子进程时用 YRP_REPLAYS_DIR 传下去
      → proxy.js / observer.js 用 process.env.YRP_REPLAYS_DIR || <数据目录>/replays
```

子进程**不知道**为什么路径变了，它只认那个环境变量；命令行直接跑
`node observer.js` 时环境变量不存在，就退回老行为（录到脚本旁边）。
换目录前会先验能不能写（真写一个探针文件再删掉），录着的时候不给换 ——
不然界面看的是新目录、子进程写的是旧目录，表现成「一直在录，列表里一个文件都不出来」。

### 改 `gui-console.bat` 前先看这里

两条硬约束，破坏之后会**双击后窗口一闪就没**：

1. **必须 CRLF 换行。** cmd.exe 解析批处理依赖 CRLF；LF-only 的文件会让它把多行
   结构拆错。用 Git Bash / 各种编辑器保存时注意别退化成 LF。
2. **必须纯 ASCII，一个中文字都不能有。** `chcp 65001` 会在 cmd 逐行读文件的过程中
   换掉代码页，cmd 用旧代码页算出的偏移去续读，**多字节字符会让它从行中间接着解析**
   ——实测第一行正常输出，紧接着就把 `echo` 的尾巴 `ho` 和上一行的句尾 `，句号。`
   当成命令去执行。所有中文都由 node 打印，那里没有这个问题。

同理，`>nul` 这三个字符要原样保留（别写成 `>/dev/null`，Windows 上那是无效路径，
cmd 会报「系统找不到指定的路径」）。这文件里没有任何需要转义的东西，正常编辑即可。
